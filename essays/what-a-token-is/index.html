What a token is

Language models never see letters or words. They see tokens. What those are, how they are chosen, and why they explain some of AI’s strangest mistakes.

November 23, 2026 · 5 min read

For a while, one of the most reliable ways to trip up a chatbot was to ask how many r’s are in “strawberry.” Systems that could write passable sonnets and explain quantum tunneling would confidently answer two.

It looked like a lapse in basic intelligence. It was actually a window into how these systems read. A language model never sees the letters s-t-r-a-w-b-e-r-r-y. It sees a few chunks of text, each replaced by a number, and the letters inside those chunks are hidden from it. Those chunks are called tokens, and once you understand them, a surprising amount of AI behavior starts to make sense.

Text in, numbers out

Neural networks only do arithmetic, so before a model can read anything, the text has to become numbers. That job belongs to a separate program called a tokenizer. It has a fixed list of text fragments, its vocabulary, and it chops your input into pieces from that list. Each piece has an ID number, and the model only ever receives the IDs.

Inside the model, each ID is swapped for an embedding, a long list of numbers that the model learned during training. From there on, everything the previous essay described happens over tokens: attention connects tokens to other tokens, and the model’s output is a prediction of the next token’s ID, which the tokenizer turns back into text.

In English, a token averages roughly four characters, or about three-quarters of a word. Common words like “the” or “house” are usually a single token. Rarer words get split: “tokenization” might become “token” and “ization.”

Why not letters? Why not words?

Two obvious alternatives both fail. Reading letter by letter makes every sentence several times longer, and the cost of attention grows with the square of the length, since every position looks at every other position. Letters also carry little meaning on their own, so the model would spend much of its effort just reassembling words.

Reading whole words fails the other way. The list of possible words never ends: names, typos, slang, new coinages, “COVID,” every language on Earth. Any word missing from a fixed list would be unreadable.

Tokens are the compromise. Frequent words get a token of their own, and anything rarer is spelled out from smaller pieces, down to single characters if necessary. A vocabulary of tens of thousands of fragments can then express any text at all. GPT-2’s vocabulary had 50,257 tokens; more recent models typically use somewhere between about 100,000 and a few hundred thousand.

How the pieces are chosen

Nobody picks the fragments by hand. The most widely used method, byte-pair encoding, began life in 1994 as a data-compression trick1 and was adapted for language models in 2016.2 It is almost embarrassingly simple:

  1. Start with every text split into single characters.
  2. Count every pair of neighboring symbols across the training text.
  3. Glue the most frequent pair into a new symbol, and add it to the vocabulary.
  4. Repeat until the vocabulary is as big as you want.

Early merges capture common letter pairs like “t” + “h.” Later ones build up syllables, then whole frequent words. The figure below runs that exact procedure, live in your browser, using the paragraphs of this essay as its training text.

(Because this essay mentions “strawberry” several times, the toy tokenizer has learned it as a single token, which real tokenizers usually don’t.) That is exactly how a real model experiences a rare name or an unusual spelling.

Go deeper: byte-pair encoding in code

Training learns an ordered list of merges. This is a minimal version of what the figure runs:

from collections import Counter

def train_bpe(words, num_merges):
    # words: Counter mapping each word to how often it appears
    seqs = {w: list(w) for w in words}
    merges = []
    for _ in range(num_merges):
        pairs = Counter()
        for w, syms in seqs.items():
            for a, b in zip(syms, syms[1:]):
                pairs[a, b] += words[w]
        if not pairs:
            break
        a, b = max(pairs, key=pairs.get)
        merges.append((a, b))
        for w, syms in seqs.items():
            out, i = [], 0
            while i < len(syms):
                if syms[i:i + 2] == [a, b]:
                    out.append(a + b); i += 2
                else:
                    out.append(syms[i]); i += 1
            seqs[w] = out
    return merges

To tokenize new text, start from characters again and keep applying whichever learned merge has the earliest rank among the pairs present, until none apply. Before any of this, text is first split on a simple pattern, roughly “runs of letters, runs of digits, runs of punctuation,” each keeping one leading space. That is why “ the” and “the” are different tokens.

Production tokenizers such as GPT-2’s work on raw bytes rather than characters.3 The base vocabulary is then exactly 256 symbols, so any text in any language or encoding can be represented, and nothing is ever “unknown.”

What tokens explain

Counting letters. If “strawberry” arrives as two or three multi-letter chunks, the model never directly sees how many r’s there are. It has to have learned the spelling of each chunk as a fact, the way you might know that “colonel” contains an l without hearing one. Models have since got much better at this, but the difficulty was never about intelligence.

Arithmetic. Numbers get chopped into pieces too, and not always along digit boundaries that make sense for adding or multiplying. Doing column arithmetic when the columns are hidden inside arbitrary chunks is hard.

Spaces and capitals. “The,” “ the” and “ THE” are typically three unrelated tokens. A model has to learn from data that they mean the same thing, which it does well for common words and less well for rare ones.

Other languages. Tokenizers are trained mostly on English text, so English gets the most efficient chunks. The same sentence in many other languages can take several times as many tokens.4 Since usage is billed per token and a model’s memory is measured in tokens, those languages are slower, more expensive and fit less into a single conversation.

Glitch tokens. In 2023, researchers found tokens such as “SolidGoldMagikarp,” a Reddit username, that sat in GPT-3’s vocabulary but almost never appeared in its training data. The model had learned essentially nothing about them, and asking it to repeat one produced bizarre, evasive answers.5 The tokenizer and the model had been trained on different text, and the gap showed.

Why it matters to you

If you use these systems, tokens are the unit everything is measured in. Prices are quoted per million tokens. A model’s context window, how much it can consider at once, is a token count. When a model stumbles over spelling, digits or an unusual name, the tokenizer is a good first suspect.

There is also something quietly odd here. The tokenizer is about the only part of a modern language model that is not learned by the model itself. It is built beforehand by simple counting, then frozen. Everything the model knows, it knows in terms of pieces chosen by a 1990s compression trick. Attention may be all you need, but first, you need tokens.
